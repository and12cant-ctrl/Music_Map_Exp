# イベント編集UI Ver.1 操作手順書

## 1. 開く

Unityの **Tools → Events → Event Editor Ver.1** を選びます。上部の「登録先カタログ」に、ゲームのEventSystemRootが使うEventCatalogSOを指定してください。画面左はProject内のイベント一覧、右は選択したイベントの8タブです。中央の境界をドラッグして幅を調整できます。

左の検索欄は名前・作者用ID・タグを検索します。「カテゴリ」で絞り込めます。選択中は▶と背景色で表示。未登録と表示されるイベントは、選択して「選択イベントをカタログへ登録」を押します。複数カタログを自動で選び分ける機能はありません。

従来の **Tools → Events → Event Database** とOdin Inspectorも残っています。上部「Inspector」は選択アセットをProjectの選択状態にします。

## 2. 新しいイベントを作る

1. 登録先カタログを選んで「新規」を押し、Assets以下の保存先を指定します。
2. 「基本」で「イベント名」「作者用ID」「カテゴリ」を入力します。新規イベントは拡張方式・無効の下書きです。
3. 開始前と判定前の文章・画像、マップアイコンを設定します。
4. 「マップへの配置」を展開し、配置の有無・最低数・重み・配置できる背景カテゴリを設定します。背景は登録済みBGCategoryListSOから選択。空リストは背景制限なしです。
5. 必要な他タブを設定し「検証」でエラーを確認します。
6. 使用する準備ができたら「基本」の「ゲームで有効」をオンにし、上部の「保存」を押します。

内部EventIdは自動生成されます。作者用IDと違い、保存データが参照するIDなので編集不可です。「複製」は新しい内部IDと重複しない作者用IDで別アセットを作ります。複製したイベント内の参照先は元の設定を維持します。

「削除」は確認後アセットをごみ箱へ移動し、各カタログの登録を解除します。確認画面に参照元を表示します。アセット削除はUndoできず、他イベントやScene等に参照切れが生じ得ます。通常の設定編集・リスト編集はUnity標準のUndo / Redoを使用できます。

## 3. 条件

「条件」→「発生条件」→「＋追加」。行をクリックして開き、「判定対象」を選びます。

| 判定対象 | 入力するもの |
|---|---|
| キャラクター能力 | キャラクター、能力値、演算子、数値 |
| 施設の関係値 | 施設、演算子、数値 |
| Flag | 登録済みFlag、＝／≠、True／False |
| ヒント所持 | 登録済みHintData、＝／≠、True／False |
| 時間帯 | ＝／≠、昼／夜 |
| イベント履歴の結果 | 登録イベント、Latest／Any／All、＝／≠、SUCCESS等 |
| 過去参加者の能力 | 登録イベント、履歴方式、能力値、演算子、数値 |

判定対象を変えると、以前の対象専用の参照・比較値はリセットされます。すべての行を満たすAND条件です。↑／↓で並べ替え、削除でその行を除きます。履歴0件はLatest・Any・Allとも不成立。Latestは最後に解決履歴へ記録された1件です。

所持金の条件は「配置条件（既存のWorld接続を使用）」に追加し、ResourceAtLeast・キーGold・比較値を設定します。意味は所持金≧比較値。これはマップ生成時の配置条件であり、拡張発生条件やPointConditionと同じ評価経路ではありません。背景カテゴリは基本タブで設定します。夜条件を入れても夜になった瞬間にイベントが自動生成されるわけではありません。

## 4. Slotと過去参加者

「Slot」→「参加枠」→「＋追加」で枠を作ります。名前、カード種類、必要数、参加方式を指定します。人物は必要数1。固定の関係者を使う場合は「固定の対象」に人物などの定義アセットを設定します。「参加カードの合計能力条件」は参加者全体の条件です。

イベントAのSlot 1の人物をBへ参加させる例:

1. Aに人物の必須Slotを作ります。
2. Aの「Outcome」で、SUCCESSのFollowUpにBを設定します。
3. Bの「Slot」に人物1人の枠を追加します。
4. 「過去イベントの同一参加者を要求」をオンにします。
5. 「参照イベント」をA、「参照Slot番号」を1にします。
6. 「履歴の選択方式」を「FollowUpの発生元インスタンス」にします。
7. 必要なら「結果で履歴を絞り込む」をオンにしてSUCCESSを選びます。

このBは、そのBを発生させたAの回を参照します。他の回のAが後で完了しても入れ替わりません。「条件に一致する最新の解決履歴」は開始時点で最新の一致履歴を参照します。どちらも同じ人物を要求し、別人物の代替は不可。現在利用できるカードがあればStart時に自動で割り当てます。

履歴がない、古いデータでSlotが未記録、Slotが空、EXPIRED、人物が利用不可の場合は開始できません。開始画面のメッセージを確認してください。古いParticipantsの順番からSlotを復元しません。固定の関係者との併用はできません。

**Slot番号は一覧の上から1、2…です。** 他イベントや既存セーブが参照しているSlotを並べ替えると番号の意味が変わります。

## 5. 時間

- 「開始後、実行までの昼夜切替回数」: Startから何回の切替で実行可能になるか。0ならすぐに解決待ちになります。
- 「未開始イベントの有効期限」: 出現から何回の切替までStartできるか。0はStart前にEXPIRED、参加者は空です。開始後は期限切れしません。
- 後続の待ち時間と重複許可: 「Outcome」の各FollowUpで設定します。

昼→夜、夜→翌昼はそれぞれ1回です。時間帯の指定は「条件」タブにあります。

## 6. HintLevel

「ポイント条件」に必要な条件を複数追加し、それぞれ「成立時の獲得ポイント」を設定します。通常の発生条件とは別に保存され、イベント解決時に評価されます。「レベル2」「レベル3」の閾値を設定し、説明文で変換を確認します。

これだけではヒントは付与されません。「Outcome」で「＋Hint」を追加してください。固定取得はHintDataを指定。ランダム取得は固定チェックを外し、HintLevelタブで候補プールを指定します。プール内のHintData編集はProjectのアセットで行います。

現在のHintDataにはMove／Density／Order／Rhythm／MaxEmo／MinEmoの分類や取得内容のフィールドがありません。これら6種を指定するUIは今回追加していません。

## 7. Outcome

「成功・失敗の判定」で使用する能力値、補正、成功目標値、ダイスの有無・個数・面数を設定します。**能力値合計＋補正＋ダイス合計≧目標値**が成功。ダイスを使わない場合も個数・面数は有効範囲のままにします。

SUCCESS／FAILURE／EXPIREDを切り替え、結果文章・画像、Effect、FollowUpを編集します。

- ＋Gold: 所持金の増減値。
- ＋Item: 装備アイテムと数量。
- ＋Hint: 固定またはランダム。レベルはPointConditionで決定。
- ＋Relation: 施設の関係値。キャラクター好感度ではありません。
- ＋Flag: 登録済みFlagと設定値。

Effectは行を開いて詳細を編集し、↑／↓で同じグループ内の順序を変えます。「従来Effect」がある場合、そちらが新しい型付きEffectより先に適用されます。

FollowUpは「＋追加」を繰り返し、B・Cなど複数のイベントを指定できます。親の解決後の待ち回数0はすぐ出現を試みます。重複許可がオフなら、予約中と発生中の同じイベントが抑止対象です。対象の発生条件・無効状態・空セル不足で出現が待たされる場合があります。

## 8. 関係図・検証・保存

「関係図」は1関係1行の閲覧図です。青い実線はFollowUp、橙の破線は履歴条件やSlotの参照。結果名も表示されます。左右のイベントノードを押すとその基本タブへ移動します。横に長い場合はスクロールできます。

「検証」は既存EventValidatorの全イベント検査です。エラー・警告・情報を区別して表示し、「該当設定へ」で修正用タブへ進みます。原因の本文は既存Validator由来の英語を含みます。

通常の入力はアセットへ反映されるため、タブ切替で失われません。上部「保存」で選択アセットと登録先カタログをディスクへ保存します。別イベントにも未保存変更がある場合はそのイベントを選んで保存するかUnity標準のProject保存を使います。下部の保存状態は選択アセットについて表示します。

旧イベントは勝手に拡張方式へ変換されません。「基本」→「実行方式」の切替だけでは旧結果は拡張結果へ移りません。既存のイベントを継続運用する場合、従来方式のまま編集できます。
