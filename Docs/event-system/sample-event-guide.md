# 神社サンプルイベント設定ガイド

## 1. サンプルの概要

このガイドは、現在の `EventDefinitionSO`、`EventCatalogSO`、Odinベースの `Event Database`、配置・予約・時間帯進行・判定・結果適用の実装を基準にしています。サンプルとして次の1件を作成しました。

- 表示名: `神社の依頼（簡易サンプル）`
- 制作者向けコード: `SAMPLE_SHRINE_REQUEST_001`
- 永続ID: `848c466237804fde8e14d27f325e9ebe`
- カテゴリ: 共有カテゴリカタログの `神社`
- 概要: マップ上の鳥居アイコンを選び、人物カードを1枚割り当てて予約します。1時間帯後に魅力と1D6で判定し、成功時は10 Goldを得ます。

元の題材にあった「開催施設の好感度60以上」「同じ施設で前提イベントに成功済み」「現在が夜」は実現していません。現在の `EventConditionKind` には施設別好感度、施設別イベント履歴、現在時間帯を読む条件がなく、それらを新設しない方針で簡易サンプルにしました。条件リスト自体は全要素を満たすAND判定ですが、必要な条件の種類がありません。

作成物と参照先は次のとおりです。

| 種類 | パス | 用途 |
|---|---|---|
| イベント定義 | `Assets/イベント/サンプル/神社の依頼（簡易サンプル）.asset` | 今回作成した唯一の新規 `EventDefinitionSO` |
| サンプル用カタログ | `Assets/イベント/サンプル/神社サンプルイベントカタログ.asset` | サンプル1件だけを登録し、本番Sceneから分離する |
| 共有カテゴリカタログ | `Assets/イベント/イベントカテゴリ.asset` | 登録済みの `神社` カテゴリを参照する |
| 画像・マップアイコン | `Assets/スプライト/マップアイコン/鳥居.png` | 旧神社カテゴリでも使用中の既存Sprite |
| UI Prefab | `Assets/Prehab/EventSystemUI.prefab` | 予約・予定一覧・実行結果を表示する既存Prefab |
| 生成補助 | `Assets/Script/Events/Editor/ShrineSampleEventCreator.cs` | 同じ設定の作成または既存サンプルの選択を行うEditorメニュー |

サンプル用カタログはどのScene・Prefabからも参照されていません。そのため、このアセットを作成しただけでは本番ゲームに出現しません。

## 2. アセットを開く手順

### Projectから直接開く

1. UnityのProjectウィンドウで `Assets > イベント > サンプル` を開きます。
2. `神社の依頼（簡易サンプル）` を選択します。
3. Inspector上部の `共有イベントカテゴリ` で `神社` が表示されることを確認します。
4. Inspectorの `基本`、`出現`、`予約`、`実行`、`結果` タブを順に開きます。

### Event Databaseから開く

1. Unityメニューの `Tools > Events > Event Database` を開きます。ウィンドウ名は `Event Database` です。
2. `カタログ` グループの `Catalog` に `Assets/イベント/サンプル/神社サンプルイベントカタログ.asset` を設定します。
3. `イベント一覧` の `SAMPLE_SHRINE_REQUEST_001   神社の依頼（簡易サンプル）   [神社]` をクリックします。
4. 右側または下側に表示されるインラインInspectorで各タブを開きます。

`Search` はイベントコードと表示名の部分一致検索、`Tag` はタグの大文字小文字を無視した完全一致フィルターです。カテゴリは `すべて`、`未設定`、`特定カテゴリ…` で絞り込めます。

### 生成補助メニュー

`Tools > Events > Create Shrine Sample Event` を選ぶと、この2アセットが存在する場合は上書きせず、イベント定義をProjectウィンドウで選択します。片方だけが存在する場合も上書きせず、Consoleへエラーを出します。

## 4. 自分で再現する手順

### 既存の生成補助を使う

1. Unityメニューの `Tools > Events > Create Shrine Sample Event` を選びます。
2. 今回のアセットが既にある場合は新規作成せず、`神社の依頼（簡易サンプル）` がProjectで選択されます。
3. Consoleに部分生成エラーが出た場合は、イベント定義とサンプル用カタログの片方だけが存在しています。生成処理は既存ファイルを上書きしません。

### Event Databaseで手作業する

1. `Tools > Events > Event Database` を開きます。
2. `新規カタログ` を押し、保存先を決めます。作成したカタログの `Category Catalog` に `Assets/イベント/イベントカテゴリ.asset` を設定します。
3. Event Databaseの `Catalog` にそのカタログを設定します。
4. `新規イベント` を押し、`EventDefinitionSO` の保存先を決めます。この操作は新しい `Persistent Id` と重複しない `Event Code` を自動生成し、選択中のカタログへ登録します。
5. Inspector上部の `共有イベントカテゴリ` で `検索して選択` を押し、`神社` を選びます。新しいカテゴリを作る必要はありません。
6. `基本` タブを開き、上の表どおりに `Event Code`、`Display Name`、`Enabled`、`Tags`、`Developer Memo`、`Sort Order`、`Priority` を設定します。`Persistent Id` は編集しません。
7. `出現` タブを開き、`Appearance` の各値と `Conditions` の `Always` を設定します。
8. `予約` タブを開き、`Scheduled`、`Required Phase Count = 1`、予約文、画像、人物スロット1件、`Appeal >= 1` の必要条件を設定します。
9. `実行` タブを開き、`Narrative`、判定前の文と画像、`Appeal + 1D6 >= 4` の判定を設定します。
10. `結果` タブで `SUCCESS` と `FAILURE` の2件を設定します。`Is Default` は `FAILURE` だけONにします。リストはnullではなく空リストにします。
11. Projectを保存します。Event Databaseで `一覧を更新`、続いて `全イベント検査` を押します。
12. 検査一覧に `神社の依頼（簡易サンプル）` または `神社サンプルイベントカタログ` を対象とする行がないことを確認します。検査対象はProject内の全 `EventDefinitionSO` です。サンプル専用カタログには他のイベントを登録していないため、他のイベントには `Not registered in the selected catalog.` の警告が表示され得ます。

`新しいGUIDで複製` は、選択イベントを複製して新しい `Persistent Id` を付け、重複しない `Event Code` を生成してカタログへ登録する実装です。複製後は両アセットの読み取り専用 `Persistent Id` が異なることを確認してください。このガイド作成時には複製操作を実行していません。

## 5. ゲーム内で確認する手順

### 現在の接続状態

`Assets/Scenes/メインバトル.unity` には、GameObject `Main` 上に `GameManager`、`MapGenerator`、`MiniMapBuilder`、`MapIconPresenter` があり、子GameObject `派遣` に `HakenTab` があります。新しい `EventSystemRoot` は接続されていません。サンプル用カタログもScene・Prefabから参照されていないため、現状のSceneをそのままPlayしてもこのサンプルは出現しません。

以下は現行コードに基づく接続・確認手順です。既存Sceneを変更しないという今回の条件に従い、接続とPlay確認は実施していません。試す場合はSceneの複製または保存しない一時変更で行ってください。

1. `Assets/Scenes/メインバトル.unity` を開き、Hierarchyの `Main` を選択します。
2. `Main` に `EventSystemRoot` を追加します。`RequireComponent` により `GameManager` と同じGameObjectで使う構成です。
3. `EventSystemRoot > Catalog` に `Assets/イベント/サンプル/神社サンプルイベントカタログ.asset` を設定します。
4. `Ui Prefab` に `Assets/Prehab/EventSystemUI.prefab` を設定します。`Reservation View`、`Execution View`、`Schedule View` は空欄のままでも、このPrefabから実行時に取得します。
5. `World State` は空欄、`Execution Handlers` は空配列にします。このサンプルは `Narrative` とGold効果だけを使うため専用ハンドラは不要です。
6. Playします。`MapGenerator` は `EventSystemRoot` とCatalogを検出すると新しい配置経路を使い、サンプルを空きセルへ1件必須配置します。
7. 鳥居アイコンのセルへ移動します。移動1セルにつき `Current Time` を1消費します。セル上では `派遣` のタブが表示され、そのボタンが新イベントの予約画面を開きます。
8. `調査担当` スロットへ人物カードを1枚ドラッグします。人物カードの魅力 `curApi` 合計が1以上である必要があります。現在のランダム人物生成は `curApi` を最低1にしています。
9. 予約画面の `予約` を押します。イベントは `Reserved` になり、割り当てたカードは完了または取消までロックされます。
10. 予約後に時間帯を1回切り替えます。`TimeManager` は各時間帯の `Current Time` を25から開始し、移動1回で1減らし、0になると昼→夜、または夜→翌日昼へ切り替えます。`Required Phase Count = 1` は、この25点を意味せず、この切替を1回待つ設定です。
11. 切替後にイベントは `Ready` になり、実行画面へ進みます。判定前文章と鳥居画像が表示されます。
12. `続行` を押すと、割り当てた人物の魅力に1D6を加え、合計4以上なら `SUCCESS`、未満なら既定の `FAILURE` を選びます。ダイス、合計、結果コードと結果文章が表示されます。
13. もう一度 `続行` を押します。成功ならGoldが10増え、失敗なら効果はありません。処理が終わると状態は成功・失敗のどちらでも `Resolved` になり、イベントはマップセルから除かれます。

`EventSystemRoot.CreateSaveData()` と `Restore(EventSaveData)` は実装されていますが、ファイルへ書き出すゲーム全体の保存・読込経路は未接続です。このサンプルについても、ゲーム再起動をまたぐ保存確認はできません。

## 6. 確認結果と未確認事項

### 確認済み

- UnityのAssetDatabase経由でイベント定義、専用カタログ、各 `.meta` が生成され、YAMLを再読込して全設定値が保存されていることを確認しました。
- イベント定義は共有カテゴリ `神社` の不変IDを保持し、専用カタログは共有カテゴリカタログとサンプルイベントを実アセット参照で保持しています。
- 鳥居Sprite参照は既存の `Assets/スプライト/マップアイコン/鳥居.png` へ解決できます。
- 生成処理は保存後に `EventValidator.Validate` を実行し、問題が1件でもあれば作成した2アセットを削除する実装です。今回の2アセットが保持されているため、生成時のサンプル単体検査は0件で完了しています。
- サンプルのイベントGUIDは専用カタログ以外から参照されず、専用カタログGUIDはScene・Prefabから参照されていません。

### 未確認・未対応

- この環境ではUnityのネイティブ画面を操作・取得できなかったため、実Inspectorのスクリーンショットは添付していません。想像画像や生成画像も使用していません。
- Unityの画面上でアセットを閉じて再度開く操作は未確認です。保存済みYAMLの再読込で設定保持を確認しています。
- 既存Sceneへの `EventSystemRoot` 接続、Play Modeでの配置・予約・時間帯進行・判定・結果表示は未実行です。
- 施設好感度60以上、同一施設での前提イベント成功、夜限定の3条件は未実装です。
- `EventSaveData` を永続ストレージへ保存する処理は未接続です。
