// ============================================================
// 感情判定システム 仕様書（主旋律＋副旋律 2パート版）
// ============================================================
//
// ■目的
// 2〜4小節の短いフレーズから、以下4種類の感情カテゴリを判定する：
//   0: 楽しい (Joy)
//   1: 悲しい (Sadness)
//   2: 恐ろしい (Fear)
//   3: 不安   (Anxiety)
//
// 判定は「主旋律パート」と「副旋律パート」の2パートを用い、
// 学習済みモデルは単一パート用を1つだけ用意し、推論時に
// 主旋律・副旋律それぞれに適用して重み付きで合成する。
//
//
// ■対象となるフレーズ条件
// - 長さ: 2〜4小節
//   - 2小節未満のフレーズは学習には使用しない（推論時は別途扱いを検討）
// - 拍子: 以下のいずれか
//   - 4/4
//   - 3/4
//   - 2/2
//   - 上記以外の拍子は、今回の学習では使用しない（入力時はエラー or 4/4扱いなど要検討）
// - パート数:
//   - 最大4パートまで存在し得るが、感情判定に使用するのは 2パートのみ。
//   - Part A を「主旋律」、Part B を「副旋律」とみなす。
//   - モデル学習時は、「単一パートのフレーズ」としてデータを扱う。
// - 音価（duration）:
//   - 許可する音価（四分音符を1.0としたときの長さ）は以下に限定する：
//       全音符:   4.0
//       二分音符: 2.0
//       四分音符: 1.0
//       八分音符: 0.5
//   - 付点、三連符、タイで細かく分割された値などは、学習データから除外するかエラー扱いとする。
//
//
// ■感情カテゴリ（4クラス）
// - 0: Joy（楽しい）
//   - 明るい、元気、前向きな印象。
//   - 一般には長調中心で、音域や跳躍は中程度、リズムも比較的はっきりしている。
// - 1: Sadness（悲しい）
//   - しっとり、哀愁、落ち着いた印象。
//   - 短調寄りで、音域はやや狭く、ゆったりしたリズムになりやすい。
// - 2: Fear（恐ろしい）
//   - 強い緊張感、ホラー寄りの怖さ、鋭く不安定な印象。
//   - 短調寄りで、音域が広い・大きな跳躍が多い・不協和感の強い動きが多い。
// - 3: Anxiety（不安）
//   - 落ち着かない、曖昧で揺らいだ印象、弱めの緊張感。
//   - 恐怖ほど強くはないが、リズムや音程が不規則で、安定し切らないイメージ。
//
//
// ■特徴量（Feature）設計（単一パート用）
// モデルは単一パートから以下の特徴量を抽出し、4クラス分類を行う。
// 主旋律・副旋律ともに同じ特徴量セットを使用する。
//
// 1) is_major
//   - 調性が長調なら 1.0、短調なら 0.0。
//   - 楽しい／悲しいの大まかな区別に使う。
//
// 2) tonic_pitch_class
//   - 主音のピッチクラス (C=0, C#=1, ..., B=11) を float で保持。
//   - 全体の雰囲気（どの音を中心にしているか）の傾向を見る。
//
// 3) pitch_range
//   - 最高音の MIDI ノート番号 − 最低音の MIDI ノート番号。
//   - 音域の広さ。恐怖や激しさとの関連を想定。
//
// 4) avg_pitch
//   - ノートの MIDI ノート番号の平均値。
//   - 平均音高。高い＝明るめ、低い＝暗め、の傾向に利用。
//
// 5) avg_duration
//   - 音符の duration（quarterLength）の平均値。
//   - 長め中心か、短め中心か（ゆったり vs 細かく動く）。
//
// 6) note_count
//   - フレーズ内のノート数。
//   - 音の密度。情報量や活動量の指標として使う。
//
// 7) rest_ratio
//   - ノートと休符を合計した要素数のうち、休符が占める割合。
//   - 静けさ・間の多さ・不安定さの指標。
//
// 8) avg_interval
//   - 連続するノート間の半音数（semitones）の絶対値の平均。
//   - メロディの動きの大きさ（滑らか vs 跳躍多め）。
//
// 9) large_leaps_ratio
//   - 連続ノート間の音程差が 7 semitones 以上（完全5度以上）である割合。
//   - 大きな跳躍の頻度。恐怖・緊張感との関連を想定。
//
//
// ■学習データ（単一パート）のフォルダ構成
// - プロジェクト直下の `data/` フォルダ配下に、感情ごとのサブフォルダを作成する：
//
//   data/
//     joy/      → Joy（楽しい）に分類される 単一パートの 2〜4小節フレーズ (MusicXML/MIDI)
//     sad/      → Sadness（悲しい）に分類されるフレーズ
//     fear/     → Fear（恐ろしい）に分類されるフレーズ
//     anxiety/  → Anxiety（不安）に分類されるフレーズ
//
// - 各フォルダ内のファイルは、そのフォルダ名に対応するラベルとして扱う。
// - 学習モデルは「単一パートのフレーズ → 感情4クラス」の対応を学ぶ。
//
//
// ■学習と推論の方針
//
// [学習フェーズ（開発時のみ実行）]
// - music21 で各ファイルを読み込み、1パート分の2〜4小節フレーズから特徴量を抽出する。
// - 特徴量ベクトル X と ラベル y を作成し、4クラス分類器（例: RandomForestClassifier）を学習。
// - k-fold クロスバリデーション（例: 5-fold）で性能を評価し、問題なければ全データで最終学習。
// - 学習済みモデルをファイル（例: emotion_model_singlepart.pkl）として保存する。
// - 学習処理は開発時にのみ行い、ゲーム中には再実行しない。
//
//
// [推論フェーズ（ゲーム中に毎回実行される処理）]
// - Unity側で作られたフレーズから、主旋律パート（Part A）と副旋律パート（Part B）を用意する。
// - Pythonスクリプトに 2パート分のフレーズ情報を渡す。
// - Python側では：
//     1) 学習済みモデル（emotion_model_singlepart.pkl）を読み込む。
//     2) 主旋律パートから特徴量ベクトル vec_main を計算し、
//        predict_proba() により感情4クラスの確率ベクトル p_main を得る。
//     3) 副旋律パートから特徴量ベクトル vec_sub を計算し、
//        同様に確率ベクトル p_sub を得る。
//     4) 以下の重み付き合成により最終確率 p_final を計算する：
//           w_main = 0.8   // 主旋律の重み
//           w_sub  = 0.2   // 副旋律の重み
//           p_final = w_main * p_main + w_sub * p_sub
//     5) p_final の各要素のうち最大のインデックスを最終ラベル（0〜3）とし、
//        対応する感情カテゴリ（Joy/Sadness/Fear/Anxiety）を返す。
// - 推論フェーズではモデルの再学習は行わない。
//   → 毎回同じフレーズに対して同じ結果が得られ、ゲームとして再現性が高い。
// ============================================================
